# 27 条验收标准（可追溯清单）

> 用户原始提示词只给出了编号分组（1~10 基础、8b/8c/8d 噪声、11~16 改口、17~23 恒定预算、6b~6i 门控）
> 与硬指标点名（8b、8c、17、18、19、22、E1），未逐条展开正文。本文件依据同一提示词的机制章节
> 逐条重述验收语义，作为 `tests/acceptance/` 用例与 `docs/ACCEPTANCE-REPORT.md` 的追溯依据。
> 映射到测试的列最终以验收报告为准。

| 编号 | 验收标准 | 说明/来源 | 对应测试 |
|---|---|---|---|
| 1 | 插件启用后无需用户干预，自主完成写入、召回、改口、压缩、遗忘 | 任务书「形态/机制一」；M0 起效 | A + E2E |
| 2 | turn 结束后异步触发写入，不阻塞对话响应 | 机制一（异步 ingest） | A/协议测试（ingest 异步返回语义） |
| 3 | 新记忆初始权重 1.0；`memory_pin`/“记住这个”权重 2.0 且 pinned=true | 机制一 | 单测 ingest/pin + F |
| 4 | 写入前四道闸门（工具结果摘要、凭据丢弃告警、短句丢弃、>0.95 去重）按序执行 | 机制一 | F1/F2/F3、test_noise |
| 5 | 实体类型沿用 LightRAG 默认分类并额外支持 Preference/Decision | 机制一 | test_extract |
| 6 | 衰减读时惰性求值：w(t)=min(10, w_last·2^(-Δt/7d))，不依赖定时任务 | 机制二 | test_weight |
| 7 | 激活仅对 injected_ids 调用；w=min(10,w+0.5·(1+boost))；boost=pinned+1/tool+1/workspace+0.2 | 机制二、红线 R5 | test_weight + E2E 注入日志 |
| 8 | 排序 score=sim×(0.3+0.7×min(1,w/5))，pinned×1.5，workspace 权重×1.2 | 机制二 | test_retrieval |
| 9 | 删除三阶段：先压缩→隔至少一轮剪枝才归档→冷区超期才真删，禁止同轮压完即删 | 机制六、红线 R4 | B、E2、test_prune |
| 10 | 卸载时撤销工具注册、系统提示词段落与事件监听，停止 Sidecar，保留数据文件 | 任务书「其他」 | E2E 卸载检查 |
| 11 | 写入时同 scope 近邻 top-5，相似度 [0.62,0.95) 才送 LLM 判 {is_same_attribute,is_contradiction,confidence} | 机制三 ① | C、test_supersede |
| 12 | 矛盾置信度 ≥0.7 触发改写；含明确否定词时阈值下调至 0.6 | 机制三 ① | C |
| 13 | 改写严格六步：edit_entity→valid_from/updated_at→w=max 不清零→同步向量→Journal→protect_until+7d | 机制三、红线 R6 | C、test_supersede |
| 14 | 改口以最新为准、静默替换不打断对话；不同 scope 各自保留不算冲突 | 机制三裁决规则 | C + test_supersede |
| 15 | 每日首次会话扫近 30 天活跃节点矛盾对兜底，产出 conflict_report | 机制三 ② | test_supersede（sweep） |
| 16 | 改口变更 Journal 记录 before/after/date/confidence/source_turn_id，7 天内可回滚 | 机制三 5；7 天回滚 | test_journal + C |
| 17 | **硬指标**：插件注入 token 总量为常数硬顶 3000，不随使用时长/轮数/图谱规模增长 | 红线 R1、机制四 | D1/D2/D3、token 交叉一致性 |
| 18 | **硬指标**：`<memory_context>` 按 1024/1536/1792/2048 动态分配（默认 1024；top1>0.8→1536；pin/高权重≥5→1792；显式 recall→2048 上限） | 机制五 | test_budget（TS node 测试） |
| 19 | **硬指标**：`<day_context>` 恒定 ≤1024（当天≤512/补召回≤312/历史≤200）；当天原文超界给全量压缩摘要 | 机制四 | D2/D4、test_daykeeper |
| 20 | 全量压缩 ≤360 token、保留最近 2 条原文、原文不删、限流 30min/20 轮 | 机制四 | test_daykeeper |
| 21 | 历史滚动摘要永远只有一份 ≤200 token，绝不逐日堆积 | 红线 R8 | D2、test_daykeeper |
| 22 | **硬指标**：注入前本地计量；超 3000 按优先级截断（system>当天>补召回>memory>历史）并告警；面板显示实测 token 与分布 | 机制四兜底 | test_budget、面板 |
| 23 | 召回结果为空则不注入任何标签（零 token 浪费）；召回失败/超时 300ms 一律旁路放行 | 机制五、红线 R7 | test_injector/旁路测试 |
| 24 | 图谱规模 < high 时完全不剪枝（时间不是删除理由），权重照常衰减且可召回、激活后回升 | 机制六门控、E1 | E1 |
| 25 | 图谱规模 > high 开启剪枝并剪到 <= low 停；> hard 强制剪 + 告警 | 机制六门控 | E2 |
| 26 | 双水位迟滞（low=high×0.8）：low~high 区间波动 10 天触发剪枝 ≤1 次；单轮最多处理 8%；连续 3 轮剪不到 low 停止并告警；三档按 scope 独立计量 | 机制六三档水位/门控 | E3/E4/E5/E6 |
| 27 | 压缩/剪枝免疫 pinned、Preference 类、活跃工作区记忆、近 7 天改过、新建 3 天保护期节点；默认 dry_run 只出报告；剪枝报告 7 天内可回滚 | 机制六剪枝动作/免疫 | test_prune + B |
